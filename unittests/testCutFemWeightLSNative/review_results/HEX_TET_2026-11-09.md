# HEX/TET local graph integration — 2026-11-09

The 3D extension starts from validated QUAD/TRI commit `9ee8a7f34993af1abbb0202382d001e55ed43ab6`. The preserved `rifat` benchmark is `0ff0669494e603be248d02c44c0a2e9b81f72b4d`. The QUAD, TRI, and LINE production headers are unchanged by this extension.

## Resulting implementation

`GraphCellIntegration.hpp` is the shared 3D controller. HEX slices call the validated QUAD kernel; TET slices call `TriangleIntegration`, which uses the shared LINE kernels. The ordinary default APIs in `CutFemWeight_LS` select these paths automatically.

HEX subdivision uses boxes. TET subdivision clips the standard tetrahedron into convex polyhedral regions. Keeping those regions avoids artificial tetrahedral interior faces and their tangencies. Slices are triangulated and integrated without refitting the parent FE polynomial. This matters for TET15: nodal interpolation on arbitrary children would not preserve the original enriched polynomial.

Each region needs a Bernstein certificate that one Cartesian partial derivative stays away from zero. Direction selection is local. Critical-point splits use the unchanged field to locate an uncut core and place cuts between the critical point and nearby roots. If that proposal is unavailable, derivative-guided subdivision is used. Uncertified regions cannot be silently accepted. If a direct control-net bound is inconclusive and no graph direction is certified, Bernstein coefficient refinement first tries to certify that the region is uncut. This prevents repeated geometric splitting of empty regions in the full TET15 quartic-bubble case.

Boundary intersections and face tangencies are collected once per region and reused by outer adaptivity. The original tetrahedral face restriction uses the TET15 bubble identity to avoid ill-conditioned high-degree resultants. Endpoint mapping is enabled only when face topology reports tangencies; ordinary graph panels use direct GK7/15. Inner kernels keep their existing fast-GK → Taylor → full-GK sequence.

Accepted moments are retained through local refinement and global error-budget redistribution. Inner errors, geometric bounds, and output rounding are propagated to the final check for every requested moment. Exact TET zero faces retain the existing endpoint trace rule, including half weights. Explicit diagnostic directions and direction cross-validation remain available.

Reference area, physical inverse-Jacobian metrics, and curved nodal-geometry cofactors use the same gradient conventions as the public API. The gradient extraction is shared with the retained TET diagnostic path.

## Reproduction and scope

From `unittests/testCutFemWeightLSNative`, run `python3 build.py --jobs 2`, `python3 run_focused.py --extended`, `python3 run.py --selection original`, `python3 run.py --selection supplemental`, `python3 compare_planar.py`, `python3 run_hex_tet_validation.py`, and `python3 validate_enriched_3d.py`. Set `BOOST_INCLUDEDIR`, `EIGEN3_INCLUDE_DIR`, and `CXX` if needed. The final GitHub workflow also repeats the independent QUAD/TRI review.

`hex_tet_summary.json` and `enriched_3d_summary.json` contain compact acceptance, the benchmark aggregates, and implementation hashes. The runner resets acceptance before testing and rejects a changed source snapshot. Full local numerical outputs remain outside the commit.

Local leak detection was disabled because LeakSanitizer cannot run under ptrace in this environment; CI uses runtime defaults. A full MPI/PETSc ex44 solve was not run. Verification uses the actual FEMuS basis and quadrature sources with the native integration and weight APIs.
